──────────────────────────────────────────────────────────────
  ARCHIVO 1: backend\.env
──────────────────────────────────────────────────────────────
Crea el archivo C:\Users\MariaFernandaSuarezD\Documents\Tesis\backend\.env
con este contenido (ya ajustado para tu computadora):

  DATABASE_URL="postgresql://postgres:30015773@localhost:5432/campolargo"
  BACKEND_PUERTO=3001
  JWT_SECRETO=clave_secreta_aleatoria_minimo_32_caracteres_cambiar

  JWT_EXPIRACION=15m
  JWT_EXPIRACION_REFRESH=7d
  NODE_ENV=development

  ¿Cómo generar claves JWT seguras? Ejecuta esto en PowerShell:
  node -e "console.log(require('crypto').randomBytes(64).toString('hex'))"
  Copia la salida y pégala como valor de JWT_SECRETO.
  Repite el comando y pega el nuevo valor en JWT_SECRETO_REFRESH.
  (Deben ser valores DISTINTOS entre sí.)

  VARIABLES OPCIONALES (para envío de correos):

  EMAIL_USUARIO=tu_correo@gmail.com
  EMAIL_CLAVE=clave_de_aplicacion_gmail

──────────────────────────────────────────────────────────────
  ARCHIVO 2: frontend\.env
──────────────────────────────────────────────────────────────
Crea el archivo C:\Users\MariaFernandaSuarezD\Documents\Tesis\frontend\.env
con este contenido:

──────────────────────────────────────────────────────────────
  ¿Qué hace cada variable?
──────────────────────────────────────────────────────────────
  DATABASE_URL          → Cadena de conexión a PostgreSQL.
                          Formato: postgresql://usuario:contraseña@host:puerto/base_datos
                          Cambia "postgres:30015773" si tu usuario o contraseña son diferentes.

  BACKEND_PUERTO        → Puerto donde corre el servidor Express (3001 por defecto)

  JWT_SECRETO           → Clave privada para firmar los tokens de acceso.
                          Mínimo 32 caracteres, completamente aleatoria.

  JWT_SECRETO_REFRESH   → Clave para los tokens de renovación (refresh).
                          Debe ser DIFERENTE a JWT_SECRETO.

  JWT_EXPIRACION        → Cada cuánto expira el token (15m = 15 minutos)
  JWT_EXPIRACION_REFRESH→ Cada cuánto expira el refresh token (7d = 7 días)

  NODE_ENV              → "development" en tu computadora, "production" en servidor real.

  VITE_API_URL          → Dirección donde el frontend busca la API del backend.
                          Si cambias el puerto del backend, actualiza esto también.


PASO 1 - INSTALAR LAS DEPENDENCIAS (solo la primera vez)
---------------------------------------------------------
Abre una terminal (PowerShell o CMD) y ejecuta estos comandos EN ORDEN:

  cd C:\Users\MariaFernandaSuarezD\Documents\Tesis
  npm install --legacy-peer-deps

  cd backend
  npx prisma generate

Luego instala también las dependencias locales del frontend:
  cd ..\frontend
  npm install --legacy-peer-deps

Espera a que todo termine. Puede tardar unos minutos.


PASO 2 - CREAR LAS TABLAS EN LA BASE DE DATOS (solo la primera vez)
--------------------------------------------------------------------
En la terminal del BACKEND ejecuta:
  npx prisma migrate dev --name inicio

Esto lee el archivo schema.prisma y crea TODAS las tablas en tu base de datos
automáticamente. Verás mensajes como "Applying migration..." - eso es normal.


PASO 3 - CARGAR DATOS DE PRUEBA (solo la primera vez)
------------------------------------------------------
Todavía en la terminal del BACKEND ejecuta:
  npm run db:seed

Esto carga datos reales de la empresa:
- Las 3 fincas (La Esperanza, San Antonio, El Palmar)
- Razas de ganado (Brahman, Senepol, Cebú, etc.)
- Animales de ejemplo
- Un usuario administrador para entrar al sistema
- Calendarios de vacunación
- Reglas de alertas automáticas

Al terminar verás algo como: "Datos cargados exitosamente"


PASO 4 - INICIAR EL SISTEMA
----------------------------
Necesitas las DOS terminales corriendo al mismo tiempo.

En la terminal del BACKEND:
  npm run dev

Verás: "Servidor iniciado en el puerto 3001" - eso significa que la API está lista.

En la terminal del FRONTEND:
  npm run dev

Verás algo como: "Local: http://localhost:5173" - esa es la dirección del sistema.


PASO 5 - ABRIR EL SISTEMA EN EL NAVEGADOR
------------------------------------------
Abre Google Chrome o cualquier navegador y ve a:
  http://localhost:5173

Verás la pantalla de inicio de sesión del sistema.

QUÉ HACER SI ALGO FALLA
------------------------

ERROR: "Cannot connect to database" o "P1001"
  - Verifica que PostgreSQL esté corriendo (busca el servicio en el Administrador de tareas)
  - Verifica que la base de datos "campolargo" exista en pgAdmin
  - Abre backend\.env y confirma que DATABASE_URL tenga el usuario y contraseña correctos
  - El formato debe ser: postgresql://postgres:TU_CONTRASEÑA@localhost:5432/campolargo

ERROR: "Invalid JWT secret" o errores de autenticación
  - Verifica que backend\.env tenga JWT_SECRETO y JWT_SECRETO_REFRESH con valores (no vacíos)
  - Deben tener al menos 32 caracteres cada uno

ERROR: "Port 3001 already in use"
  - Algún proceso ya está usando ese puerto
  - Ejecuta: netstat -ano | findstr :3001
  - Luego cierra ese proceso desde el Administrador de tareas

ERROR: "VITE_API_URL is undefined" o frontend no puede conectar al backend
  - Verifica que el archivo frontend\.env exista y tenga: VITE_API_URL=http://localhost:3001/api
  - Asegúrate de que el nombre empiece con VITE_ (mayúsculas)
  - Reinicia el servidor de Vite después de cambiar el .env

ERROR: "Module not found" o errores de TypeScript
  - Vuelve a ejecutar npm install en la carpeta que da error

ERROR: "Prisma Client not generated"
  - Ejecuta en backend: npx prisma generate

ERROR en el frontend: pantalla en blanco
  - Abre las herramientas del desarrollador (F12) y mira la consola
  - Asegúrate de que el backend esté corriendo primero

  Fincas        → Las 3 fincas con panel de detalle que muestra todos sus animales

  Reportes      → Descarga de reportes en PDF y Excel
  Seguridad     → Gestión de usuarios y contraseñas
  Auditoría     → Historial completo de acciones en el sistema
